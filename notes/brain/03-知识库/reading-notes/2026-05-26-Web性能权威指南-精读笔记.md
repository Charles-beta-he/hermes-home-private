## 章节地图 / Chapter map

1. **Networking 101**：用延迟、带宽、TCP、UDP、TLS 等底层约束解释为什么“网页慢”往往不是单个接口慢，而是多段网络成本叠加。
2. **Latency and bandwidth primer**：区分传播延迟、最后一公里延迟、核心网带宽与边缘带宽；性能优化应优先减少往返次数而不只是追求吞吐。
3. **TCP performance**：理解三次握手、拥塞控制、慢启动、窗口缩放、队头阻塞；短连接和小资源会放大握手与慢启动成本。
4. **TLS / transport security**：安全层增加握手与证书验证成本；会话恢复、连接复用和现代协议可以把安全成本摊薄。
5. **Wireless networks**：移动网络的无线接入、功耗状态、信号质量和调度延迟会让同一应用在移动端表现显著不同。
6. **HTTP/1.x**：keep-alive、多连接、pipelining、domain sharding、合并/雪碧/内联等历史优化都是为了绕过 HTTP/1.x 的串行与连接限制。
7. **HTTP/2**：二进制分帧、流/消息/帧、多路复用、优先级、单 origin 连接、流量控制和 server push 改变了资源组织策略。
8. **Browser APIs and protocols**：浏览器端性能还受 fetch/XHR、缓存、流式传输、WebSocket、Server-Sent Events、WebRTC 等 API/协议能力约束。

## 10 条关键概念 / examples

1. **Speed is a feature**：网络性能是产品体验的一部分；延迟每增加一个 RTT，交互感知都会被放大，尤其在移动网络和跨地域访问中。
2. **Latency 与 bandwidth 不是同一问题**：增加带宽不能消除光速、路由、排队、无线调度造成的等待；小对象/多请求页面通常先被延迟限制。
3. **RTT 是前端架构指标**：DNS、TCP、TLS、HTTP 请求、重定向都会消耗 RTT；减少串行 RTT 往往比微调单个 handler 更有效。
4. **TCP slow start 影响短连接**：新连接初始拥塞窗口有限，多个小资源如果反复新建连接，会反复经历慢启动。
5. **Keep-alive 是基础优化**：HTTP/1.x 的持久连接减少握手、复用拥塞窗口；后续资源可以受益于已经热起来的连接。
6. **HTTP pipelining 的实践受限**：理论上可减少等待，但队头阻塞与中间设备兼容性让它没有成为主流通用解。
7. **Domain sharding 是历史权衡**：为绕过每域连接数限制而拆域名，会增加 DNS/TCP/TLS 成本；HTTP/2 下通常应避免继续滥用。
8. **合并/雪碧/内联不是永恒最佳实践**：在 HTTP/1.x 下减少请求数有价值；在 HTTP/2 下过度合并会破坏缓存粒度和优先级调度。
9. **HTTP/2 multiplexing 改变瓶颈形态**：多个流共享一个连接，减少 HTTP/1.x 多连接竞争；但 TCP 层丢包仍可能影响连接内所有流。
10. **缓存与连接策略要一起看**：资源缓存命中可以消除网络请求；未命中时还要考虑 DNS、连接复用、TLS、协议版本、优先级和服务端响应。

## 3 个实践练习

1. **瀑布图 RTT 标注练习**：选择一个常访问页面，在浏览器 Network 面板中标注 DNS、TCP、TLS、TTFB、content download；写出哪些等待属于 RTT 串行成本，哪些属于带宽/服务端成本。
2. **HTTP/1.x 到 HTTP/2 资源策略练习**：列出一个前端项目的 JS/CSS/image 资源；分别设计 HTTP/1.x 下的合并/雪碧策略和 HTTP/2 下的缓存粒度/优先级策略，说明哪些老优化应撤销。
3. **移动网络预算练习**：假设 4G 高延迟环境，把首屏预算拆成 DNS/TCP/TLS/HTML/API/静态资源；给出“减少 2 个串行 RTT”的具体改造方案（preconnect、连接复用、合并跳转、服务端聚合等）。
