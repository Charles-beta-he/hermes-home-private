## 章节地图 / Chapter map

1. **第1章 了解Web及网络基础**：建立 Web、HTTP、TCP/IP、DNS、URI/URL 的共同语言，先解决“HTTP 在整条网络链路里处于哪一层、做什么”。
2. **第2章 简单的HTTP协议**：解释客户端/服务器通信、请求-响应模型、无状态、URI、方法、持久连接与 Cookie 状态管理，是日常接口联调的最小知识面。
3. **第3章 HTTP报文内的HTTP信息**：拆解请求报文/响应报文结构、传输编码、多部分对象、范围请求、内容协商，进入“抓包可读”的层次。
4. **第4章 返回结果的HTTP状态码**：系统梳理 2XX / 3XX / 4XX / 5XX，帮助把“请求失败”进一步分解为语义清晰的服务端契约结果。
5. **第5章 与HTTP协作的Web服务器**：从虚拟主机、代理/网关/隧道到缓存，说明一次 HTTP 交互背后并不只有“浏览器直连源站”这一种拓扑。
6. **第6章 HTTP首部**：聚焦通用首部、请求首部、响应首部、实体首部、Cookie 相关首部和其他扩展首部，是缓存、认证、协商、跨层调试的核心章节。
7. **第7章 确保Web安全的HTTPS**：从 HTTP 的明文缺陷切入，说明“加密 + 认证 + 完整性保护”为何是现代 Web 的默认前提。
8. **第8章 确认访问用户身份的认证**：比较 BASIC、DIGEST、SSL 客户端认证、表单认证，帮助区分“传输安全”和“身份可信”不是一回事。
9. **第9章 基于HTTP的功能追加协议**：把 HTTP 当作演化基座，讨论 SPDY、WebSocket、HTTP/2、WebDAV 等扩展能力，看到协议家族如何突破原始瓶颈。
10. **第10章 构建Web内容的技术**：把协议与 HTML、动态 HTML、Web 应用、数据格式/语言联系起来，建立“HTTP 不是孤立背诵题，而是内容承载基础设施”的视角。
11. **第11章 Web的攻击技术**：从输出转义缺陷、设计/设置缺陷、会话管理疏忽到其他漏洞，收束为“懂 HTTP 才能真正理解 Web 攻击面”。

## 10 条关键概念 / examples

1. **HTTP 只是 Web 栈中的应用层协作协议**：要真正理解一个请求为什么失败，往往要把 HTTP 放回 DNS、IP、TCP、TLS、代理、缓存组成的全链路里看。
2. **请求-响应模型决定了调试入口**：前端 Network 面板、curl、抓包工具本质上都在帮助你观察 request line、headers、body 与 response line、headers、body 的交换。
3. **无状态不等于无上下文**：HTTP 协议本身不保存状态，但 Cookie / Session / Token 等机制是在协议之上补出来的状态管理层。
4. **URI 与方法共同定义“意图”**：同一资源 URI 在 GET / POST / PUT / DELETE 下表示不同语义，后端 API 设计与前端调用约定都依赖这层契约。
5. **持久连接是性能与稳定性的基础设施**：减少反复建连不仅节省通信量，也影响队头等待、吞吐与移动网络下的真实体验。
6. **报文编码和传输策略会影响可观测性**：压缩传输、分块传输、多部分对象、范围请求等机制让“看得到 200”不代表“拿到的是你以为的数据形态”。
7. **状态码是业务与协议之间的语义桥**：200/204/206、301/302/304、400/401/403/404、500/502/503 不只是数字，而是调试分诊和接口契约管理的索引。
8. **首部字段承载了大量隐形规则**：缓存控制、内容协商、认证、Cookie、跳转、范围请求、代理行为几乎都通过 header 生效；只看 body 容易误判问题。
9. **HTTPS 解决的是“传输可信”，不是“应用无漏洞”**：即便全站 HTTPS，若认证、授权、输出编码、会话管理设计错误，攻击面依然存在。
10. **HTTP 的演进方向是“减少瓶颈、增强双工与安全能力”**：SPDY 到 HTTP/2、再到 WebSocket / WebDAV 等扩展，说明实际工程需求一直在推动 HTTP 从文档传输走向应用平台。

## 3 个实践练习

1. **抓包语义练习**：任选一个自己项目的登录或列表接口，用浏览器 Network 面板或 curl `-i` 输出完整请求/响应，手工标注请求方法、URI、状态码、关键首部、Cookie / Token、缓存指令，并解释每一项为何存在。
2. **状态码与错误分诊练习**：为一个现有后端接口列出 200 / 400 / 401 / 403 / 404 / 409 / 500 的触发条件与前端展示策略，检查是否存在“全部返回 200 + message 字段兜底”的反模式。
3. **安全与会话练习**：审视一个表单登录流程，分别回答传输层是否 HTTPS、身份校验如何做、会话如何续期/失效、是否存在弱 Cookie 配置、是否对输出做上下文相关转义，并写出最优先的两项修复建议。

## 可落地到当前前端/后端/工程化能力的应用点

**把《图解HTTP》沉淀为“接口链路诊断基线”并接入日常交付**：

- 前端侧：每次联调不仅看接口“通不通”，还要检查方法语义、状态码分层、内容类型、缓存策略、Cookie / Token 行为、跨域首部与重定向链。
- 后端侧：接口设计从一开始就明确资源 URI、方法约束、错误码分层、鉴权位置、幂等性与缓存语义，避免把协议层问题埋进业务字段。
- 工程化侧：在项目验收模板中加入最小 HTTP 证据表（request/response 样例、状态码矩阵、关键首部、认证方式、缓存/重定向策略）。
- 对 Hermes / 技能树：可派生一个 `http-debugging-baseline` 技能，把抓包、状态码分诊、首部检查、Cookie / Session / Token 验证、安全要点收敛成统一 checklist。
