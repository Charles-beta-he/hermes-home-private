## 章节地图 / Chapter map

### 第一阶段：从“编码”与“远距离通信”建立问题意识（第1–6章）

#### 第1章 至亲密友
1. 开篇不是直接讲 CPU，而是先问“如何把信息传给另一个人”。
2. 这一章的功能是把计算问题还原为通信问题：你必须先能表示、区分、传递状态，后续一切电路与程序才有意义。

#### 第2章 编码与组合
3. 从简单约定到组合规则，核心问题变成：有限状态如何承载更多语义。
4. 这为后面“用多个 bit 组合出字符、数字、指令、地址”打基础。

#### 第3章 布莱叶盲文与二进制码
5. 公开摘录已直接给出关键支点：布莱叶点位天然是二元状态，因此非常适合引出二进制表示。
6. 本章的重要性在于把抽象的 0/1 拉回可触摸的现实编码系统，让“二元状态承载信息”变得直观。

#### 第4章 手电筒的剖析
7. 从布莱叶这类静态编码进入时序编码：手电筒开/关可表达信号序列。
8. 这里其实是在训练“时间上的 bit 流”意识，为通信线路和时钟节奏铺路。

#### 第5章 绕过拐角的通信
9. 当发送者与接收者不再面对面时，问题升级为“如何跨介质稳定传信”。
10. 这一步把编码问题从个人约定推向系统设计：信号、路径、误解成本、同步方式都开始出现。

#### 第6章 电报机与继电器
11. 电报码把“远距离编码”推进到工程实现，继电器则把抽象状态落实为可重复切换的电气装置。
12. 这一章是从通信走向计算的桥：一旦开关状态可机械/电气复制，逻辑电路就有了材料基础。

### 第二阶段：从十进制直觉过渡到二进制世界（第7–9章）

#### 第7章 我们的十个数字
13. 先回到人类熟悉的十进制，解释“数位制”本身是编码规则，而不是自然法则。
14. 读这一章的重点不是会数数，而是理解“位置 + 基数 = 表示能力”。

#### 第8章 十的替代品
15. 一旦承认十进制只是习惯，就能自然接受别的进位系统也成立。
16. 这一步是为了消除心理阻力：计算机采用二进制不是怪癖，而是工程上最稳、最容易实现的选择。

#### 第9章 二进制数
17. 二进制在这里完成正式登场：bit 序列如何表示数值、如何扩展范围、如何和十进制互转。
18. 它把前面“点/光/开关”的二元状态统一成数学表达，后续逻辑和算术都在此基座上展开。

### 第三阶段：从开关到逻辑、再到存储与控制（第10–17章）

#### 第10章 逻辑与开关
19. 逻辑命题和电路开关开始一一对应：真/假可映射为通/断。
20. 这说明计算不是“会思考的魔法”，而是状态切换遵循规则后的可组合结果。

#### 第11章 门
21. 与、或、非等逻辑门把简单开关组织成可复用的计算积木。
22. 从这一章起，系统设计的关注点从“一个开关能做什么”升级为“多个规则单元如何组合”。

#### 第12章 二进制加法器
23. 逻辑门第一次承担明确算术职责：通过半加器、全加器这类思路把数值运算电路化。
24. 它证明“算术”也能被还原成布尔组合，而不是必须依赖人脑直觉。

#### 第13章 如何实现减法
25. 这一章通常会把补码/取反加一一类思想引入进来，说明减法也可统一为加法体系的一部分。
26. 读到这里应意识到：优秀系统设计追求的是运算规则收敛，而不是为每件事造一套孤立机制。

#### 第14章 反馈与触发器
27. 反馈让电路不再只会“瞬时计算”，还可以“记住之前发生过什么”。
28. 触发器的意义在于把计算从纯组合逻辑推进到时序逻辑，也就是从“算一次”升级到“带状态地持续运转”。

#### 第15章 字节与十六进制
29. 当 bit 数量增多，必须引入更高层表示法来管理复杂度；字节与十六进制就是这种工程压缩语汇。
30. 这一章是程序员世界的重要入口：它把底层二进制转换成更可读、更可定位的操作单位。

#### 第16章 存储器组织
31. 状态一旦可保持，就需要系统化地组织、寻址、读取和写入。
32. 本章把“记住一个 bit”推进到“管理大批 bit”，从而形成真正可用的存储系统观。

#### 第17章 自动操作
33. 自动操作意味着电路不只被人手动触发，而是能按节奏自行读取状态、执行步骤、推进流程。
34. 这是控制器和程序执行机制的前夜：你开始看到“机器按规则自己跑起来”的雏形。

### 第四阶段：从芯片到处理器、总线与操作系统（第18–22章）

#### 第18章 从算盘到芯片
35. 本章把计算工具的历史压缩回看：从人工辅助到电子集成，核心是“更高速度、更高可靠性、更高集成度”。
36. 它帮助读者理解芯片不是突变发明，而是长期把计算规则物化、微型化的结果。

#### 第19章 两种典型的微处理器
37. 处理器在这里从抽象概念变成结构对象：寄存器、算术逻辑、指令、控制、寻址方式开始并列出现。
38. 公开摘录里关于“取指令”“每次一个字节”“完整指令周期需要多个时钟周期”的描述，正好证明本章已进入处理器时序与执行层面。

#### 第20章 ASCII码和字符转换
39. 本章把“数字机器如何处理文本”讲清：字符并不神秘，它们也是编码表中的整数。
40. 这一步把人类语言重新接回机器系统：程序最终处理的是编码后的字符、字节与转换规则。

#### 第21章 总线
41. 当 CPU、存储器、I/O 不再孤立存在，系统就需要公共通道来交换地址、数据与控制信号。
42. 总线的意义在于把“部件能工作”升级为“部件能协同工作”。

#### 第22章 操作系统
43. 硬件足够复杂后，必须出现软件层来抽象设备、调度资源、提供统一运行环境。
44. 因而操作系统不是附属品，而是把底层机器变成“可供程序稳定使用的平台”的关键中介。

### 第五阶段：从数值表示到高级语言与图形界面（第23–25章）

#### 第23章 定点数和浮点数
45. 整数表示足够解释计数，却不足以覆盖现实世界连续量；于是需要定点与浮点表达精度、范围和误差权衡。
46. 这一章把“计算机为什么会有精度问题”从经验现象还原成表示方案选择。

#### 第24章 高级语言与低级语言
47. 当机器层面足够清楚后，语言层的问题就变成：如何让人类以更高抽象表达意图，再被翻译回机器可执行形式。
48. 这章是从硬件走回软件开发者视角：编程语言不是脱离机器的魔法，而是建立在底层表示与执行模型之上的组织工具。

#### 第25章 图形化革命
49. 全书最终落到人与计算机交互方式的改变：图形化界面让复杂系统变得可见、可操作、可普及。
50. 以这一章收尾很有代表性：本书不是为了把读者困在门电路里，而是让你理解今天所见一切软件体验都能回溯到前面的编码、逻辑与系统结构。

## 12 条关键概念 / examples

1. 计算机原理可以从“编码与通信”而不是“高等数学”进入。
2. 编码的本质是：用有限状态稳定地区分并传递意义。
3. 二进制不是神秘信仰，而是最适合开/关物理实现的工程表示法。
4. 逻辑与电路之间可以建立一一映射，因此推理规则能物化成硬件行为。
5. 加法器说明算术可被拆成布尔运算的组合，而不是必须保留为黑箱能力。
6. 反馈与触发器把“会算”推进为“会记”，这是时序系统的核心转折点。
7. 字节、十六进制、地址空间都是为了让海量 bit 变得可管理、可定位、可调试。
8. 指令周期揭示了程序执行的真实面貌：取指、译码、执行都需要节拍与控制。
9. ASCII 证明文本在机器里也是数字；字符处理本质上是编码转换。
10. 总线与操作系统分别解决“硬件如何协作”和“软件如何稳定使用硬件”两个层次的问题。
11. 浮点数提醒我们：计算机不是无限精确地“表示现实”，而是在表示范围、精度和成本之间取舍。
12. 高级语言与图形界面并没有抹去底层，只是把复杂性逐层封装给人类更友好的接口。

## 学习主线 / 推荐二刷顺序

1. 第一遍按书的原顺序阅读，重点不是背概念，而是抓住“编码 → 二进制 → 逻辑 → 算术 → 存储 → CPU → OS → 语言 → GUI”的单线递进。
2. 第二遍把第 1–6 章当作“为什么必须先理解编码与通信”，把第 10–17 章当作“硬件计算核心”，把第 19–25 章当作“现代程序员最常接触的抽象层”。
3. 第三遍做一张三栏对照表：物理层对象（开关/电线/时钟）— 结构层对象（门/寄存器/总线）— 软件层对象（指令/进程/字符/语言/UI）。
4. 第四遍把每章都映射到一个今天仍常见的工程问题：编码乱码、浮点误差、性能瓶颈、协议调试、编译/解释差异、状态机设计、事件循环等。

## 5 个实践练习

1. 练习 A：用前端页面做一个“布莱叶/二进制/ASCII”三向可视化小工具
   - 输入字符后，同时显示布莱叶点位、二进制 bit 串和 ASCII/Unicode 编码值。
   - 验收：能直观看到“字符只是编码表映射”的事实。

2. 练习 B：实现一个 8-bit 二进制加法器演示器
   - 用 JS 写半加器/全加器可视化，把每一位的进位过程画出来。
   - 验收：用户能逐位观察 carry 如何传播，并理解加法器不是黑箱。

3. 练习 C：写一个最小状态机，模拟“取指-译码-执行”循环
   - 不必实现真实 CPU，只要有内存数组、程序计数器、几条玩具指令即可。
   - 验收：可以看到程序计数器变化、每周期取到的字节、执行后的寄存器状态。

4. 练习 D：做一个固定小数 vs 浮点数误差对比实验
   - 演示 `0.1 + 0.2 !== 0.3` 以及用定点缩放规避误差的方式。
   - 验收：能把“数值误差”解释回表示法，而不是停留在语言吐槽层面。

5. 练习 E：从 HTTP/JSON 调试回看“编码系统”
   - 抓一次真实接口请求，逐层观察 URL 编码、header、body 字节、字符集、JSON 文本。
   - 验收：能把日常前端/全栈调试问题和本书的编码视角打通。
