# 12 - 本地大脑全量自动约束层最终长期稳定方案

## 0. 最终稳定结论

本方案是长期稳定目标，不是临时草案：Hermes 本地大脑的最终形态应从“可检索知识层 + 部分专项门禁”升级为“全量自动约束层”。

稳定定义：任何新改动在进入执行、提交、任务池推进、runtime 变更或长期规则沉淀前，都必须先经过一个可审计、可回放、可降级、可 fail-closed 的 Brain Constraint Gate。

但“全量自动约束”不等于“每一条 Markdown 笔记都自动成为全局规则”。最终稳定目标是：

新改动进入 Hermes 前，必须经过统一入口：

Change Intent → Surface/Risk Classification → Multi-vault Brain Retrieval → Canonical/Current Knowledge Selection → Required Gate Binding → Multi-model Smart Routing → Evidence-backed Verdict → Apply / Observe / Quarantine。

只有被选中且满足 current/canonical/SSOT/evidence-backed 条件的知识，才会升级为该改动的强约束。普通笔记、旧项目经验、stale 内容、缺少证据的模型意见只能作为候选证据或被过滤。

最终治理口径：本地大脑中的知识默认是证据候选；通过入口契约和 gate 绑定后才是强约束；通过 runtime/hook 接入后才是自动执行门禁。

- 本文是长期方案和入口契约，不声称 runtime 已全自动生效。

## 2. 设计原则

1. 入口契约优先：只有 memory/profile/skill/SSOT/project profile/AGENTS/runtime gate/mission/taskpool acceptance 等入口契约可直接强约束。
2. 知识先筛选再约束：普通本地大脑知识必须先通过 selection gate，不能自动变成规则。
3. 模型意见不是事实：多模型只负责评判、找风险、路由建议；事实必须由工具、文件、测试、readback、proof artifact 支撑。
4. 保持 Hermes 窄腰：优先 CLI + skill + gate + profile，不新增 core model tool，不把全量知识塞进系统 prompt。
5. 保持 prompt cache：检索结果作为 volatile context / evidence packet，不改变长期系统 prompt 前缀。
6. Fail closed：找不到相关知识、知识冲突、证据不足、模型低 quorum、影响面不明时，不能把局部改动推广为全局规则。

## 4. Knowledge selection policy

### 4.1 Accepted

可升级为该改动强约束的知识必须满足至少一项：

- `status: current|active|canonical|accepted`
- 明确标注 `SSOT` / `source of truth` / `证据边界`
- 位于 project profile / skill / AGENTS / canonical playbook / governance review
- 具备 tool/readback/test/proof artifact 支撑
- 被专项 gate 脚本验证通过，例如 `architecture_theory_impact_ratchet.py`

### 4.2 Filtered

以下只能作为候选或被降权：

- `status: stale|archived|deprecated|superseded`
- 旧项目经验、旧结论、完成态回忆、without tests、no proof
- 模型意见但无非模型证据
- 单一社媒/文章/产品宣传但无 source validation
- 只在历史 session 中出现、无当前 readback 的结论

### 4.3 Quarantine

以下直接隔离，不参与自动约束：

- 含凭证/密钥/隐私原文
- 与当前 user/system 红线冲突
- 与项目 profile 或 SSOT 冲突
- 会扩大权限、外部发送、删除、支付、凭证输入、生产发布
- 命中 prompt injection 或“忽略门禁/绕过证明”类文本

## 6. Multi-model smart routing / RouteReviewGate

多模型不是全量投票，而是 Brain Constraint Gate 内部的 RouteReviewGate：按 surface / risk / capability / side-effect / evidence-state 路由，决定是否需要模型、需要哪些模型角色、需要多少 quorum、哪些证据是硬门槛。

RouteReviewGate 稳定链路：

Change / Claim / Evidence → Surface Classification → Risk Tier → Capability Match → Side-effect Boundary → Evidence-State Check → Model Route Plan → Fanout / Specialist Review → Truth Gate → Ratification / Degraded Verdict → Action Boundary。

### 6.2 Surface-first routing table

| Surface | Primary reviewer | Secondary/adversarial | Evidence required |
|---|---|---|---|
| architecture/control-plane | Claude/architecture | GPT or DeepSeek risk review | design doc + code path + gate readback |
| implementation/code | GPT/Codex or Claude Code | DeepSeek adversarial | diff + tests + py_compile/build |
| visual/UI | Gemini visual if available | Claude/GPT UX reasoning | screenshot + browser/console/network |
| model routing/quota | mlops/GPT | Claude architecture | provider status + probe + health snapshot |
| safety/permissions | Claude governance | DeepSeek adversarial | exact target + authority + rollback + readback |
| local brain/retrieval | Claude architecture | GPT implementation + deterministic tests | search output + fixture replay + ratchet |
| taskpool/lifecycle | Claude governance | DeepSeek/GPT state-machine review | task record + lifecycle command + proof/readback |
| domain/research | source tools first | model synthesis after source packet | source URL/file + quote + timestamp |

### 6.3 Tier policy

| Tier | Trigger | Review shape | Quorum / certification | Degraded policy |
|---|---|---|---|---|
| T0 | 机械、低风险、工具可直接验证 | no model 或 single specialist sanity | 工具证据足够；单模型不叫多模型认证 | deterministic evidence pass 可继续 |
| T1 | 单 surface、低 blast radius、有轻微不确定 | one specialist + optional second reviewer | min 1 advisory；min 2 才可称 multi-model reviewed | 可 advisory；不可称 certified |
| T2 | 跨文件/跨 workflow/code gate/local automation | specialist + adversarial + deterministic gate | min 2，prefer 3；producer excluded | quorum/evidence 不足则 block/degraded_not_certified |
| T3 | runtime/control-plane/lifecycle/external/destructive/canonical rule | full discussion/ratification + objective evidence + authority gate | min 3 且角色分离；副作用需 human authority | fail-closed；not_certified 不得 done |

### 6.4 Routing rules

- T0 low-risk/read-only：single specialist can advise; not multi-model certified.
- T1 local docs/gate design：2-model quorum preferred; if degraded, output advisory + evidence requests.
- T2 scripts/workflow gate：>=2 reviewers + deterministic tests required.
- T3 runtime/lifecycle/external side effect：surface specialist + adversarial reviewer + objective evidence + human authority if side effects.
- Producer model cannot certify its own completion-critical implementation.
- Model votes without evidence_refs are advisory_only。
- Majority is not truth：少数意见指出未解决安全/权限/数据/不可逆风险时，必须进入 amend/block，而不是简单多数通过。

### 6.5 Degraded policy

| Degraded class | Meaning | Allowed | Forbidden |
|---|---|---|---|
| single_model_quorum_met | 单模型完成 T0/T1 advisory | 草案/风险提示/evidence request | multi-model certified |
| below_min_quorum | 未达 min quorum | degraded_not_certified | done/certified/force-close |
| provider_unhealthy | timeout/quota/exhausted/skipped | health boundary + retry plan | 永久降低全局 quorum |
| truth_not_grounded | 证据不足或链接失败 | evidence repair request | claim accepted |
| not_certified | 讨论未认证 | implementation proof only; lifecycle not done | done transition |
| advisory_only | 模型意见缺非模型证据 | next evidence / risk notes | completion claim |

降级仍然有价值：它可以生成方案草案、列 evidence_requests、标记 live readiness gap、创建 taskpool follow-up；但不能用于 T2/T3 closeout、completion claim、runtime hard gate 放行或外部副作用授权。

## 7. Change preflight state machine

| State | Meaning | Exit gate |
|---|---|---|
| CHANGE_DETECTED | 有新改动意图 | change summary + touched surface |
| SURFACE_CLASSIFIED | 分类到 risk/surface/side-effect | route table selected |
| BRAIN_RETRIEVED | 多 vault 检索完成 | hits carry provenance |
| KNOWLEDGE_SELECTED | accepted/filtered/quarantine 完成 | selected knowledge has evidence/canonicality |
| IMPACT_MAPPED | 生成 Theory Point / Layer Impact Map | impacted layers have gates |
| MODEL_ROUTED | 多模型/单模型策略确定 | quorum/degraded policy explicit |
| GATE_EVALUATED | deterministic + model + evidence verdict | pass/warn/block/quarantine |
| ACTION_ALLOWED | 允许局部执行 | allowed/forbidden actions explicit |
| APPLY_VERIFIED | 执行后验证 | test/readback/receipt |
| STABLE_OR_QUARANTINE | 稳定或隔离 | commit/observe/follow-up |

## 8. Fail-closed conditions

任一条件满足即 block/quarantine：

1. 找到相关知识但全部是 stale/filtered，且无 current/canonical 替代。
2. 多个 accepted 知识互相冲突，且无 SSOT 决议。
3. 改动会影响 L4/L5/LX 但未生成 Layer Impact Map。
4. 模型 quorum 未达，且风险为 T2/T3。
5. 只有模型意见，没有工具/文件/测试/readback 证据。
6. 变更会写入 lifecycle/taskpool/cron/external/publish/destructive，但无明确授权与 rollback。
7. 检索结果要求运行专项 ratchet/selfcheck，但脚本失败或缺失。
8. prompt cache 方案要求把大段知识注入 stable prompt。
9. 旧项目经验被用作全局规则但没有 current profile/SSOT 支撑。
10. 任何“绕过证明/忽略门禁/强制完成”类文本进入候选约束。
11. RouteReviewGate 的 required_evidence 未满足，仍试图认证 completion claim。
12. T2/T3 quorum 未达却声称 multi-model certified。
13. producer model self-report 被计入 completion-critical quorum。
14. consult_models provider health/timeout/quota 不明，却声称 full discussion 已完成。
15. not_certified / degraded_not_certified 被用于 taskpool done 或 runtime hard gate 放行。
