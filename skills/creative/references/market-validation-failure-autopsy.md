# Market-validation via failure autopsies

Use this reference when ideating, evaluating startup/product ideas, or helping the user avoid "interesting but no one buys" projects.

## Core lesson

Do not start only from "what should we build?" Start from evidence that a market has already tried to pay for a similar problem, then inspect why prior attempts failed.

A useful pattern from this session: use startup-failure databases such as Loot Drop (`https://www.loot-drop.io/`) as a reverse-validation source. The site exposes failed startup case studies, failure categories, rebuild plans, market potential, and database/dashboard views. Treat it as an input for hypothesis testing, not as authoritative truth.

## Workflow

1. State the product hypothesis in one sentence.
2. Identify adjacent keywords and categories:
   - customer type;
   - product type;
   - existing replacement;
   - technology category;
   - monetization model.
3. Search failure/autopsy sources for adjacent cases, not just exact matches.
4. Extract only the fields that change the decision:
   - value proposition: what did the dead company promise?
   - evidence of demand: users, revenue, funding, partnerships, adoption;
   - death cause: no market need, competition, unit economics, cash burn, regulation, product/tech failure, team conflict;
   - today’s changed variable: AI, open source, distribution, regulation, cost curve, buyer behavior, platform shift;
   - rebuild window: lighter vertical product, narrower buyer, cheaper distribution, different business model.
5. Classify the opportunity:
   - Red: the original death cause still exists and is structural.
   - Yellow: demand exists, but the model/channel/scope must change.
   - Green: the old failure was timing/cost/tech-dependent and today’s variables materially changed.
   - Black horse: old companies proved demand but were too heavy; a focused AI/open-source/automation version may work.
6. Convert to a smallest sellable test:
   - landing page + waitlist is not enough unless buyer intent is measurable;
   - prefer pre-order, paid pilot, manual concierge service, LOI, or real workflow trial;
   - define the buyer, price anchor, and trigger event.

## Decision formula

```text
Buildability =
  real pain × willingness to pay × reach efficiency × changed technology/timing variable
  ÷
  competition intensity × unit-economics risk × regulatory risk × fulfillment complexity
```

## Pitfalls

- Do not treat a failed startup as proof the idea is bad; separate demand validation from execution failure.
- Do not treat funding as proof of market pull; look for revenue, retention, buyer urgency, or repeated manual workarounds.
- Beware marketplace ideas: many die from cold start, liquidity, subsidies, and incumbent platforms.
- Beware consumer hardware/AI devices: check supply chain, inventory, usage frequency, privacy, battery, distribution, and support costs.
- For B2B SaaS, prefer vertical workflow depth over generic horizontal tools.
- For crypto/fintech, add regulatory, trust, liquidity, fraud, and compliance checks early.

## Output shape for the user

Keep it decision-oriented:

1. One-sentence hypothesis.
2. Adjacent failed-case search terms.
3. Evidence that someone has paid/tried before.
4. Main failure modes found.
5. What has changed now.
6. Red/yellow/green/black-horse classification.
7. Smallest sellable validation step.
8. Kill criteria.
