## Control-plane resume verification

When a governed mission/taskpool/control-plane workflow is unblocked and the user asks to “continue,” do not stop at recording the decision. Verify the canonical ledger, clear the human gate through the real decision command/API, wake the executor or scheduler, then read back fresh evidence. See `references/mission-control-resume-verification.md` for the detailed checklist and pitfalls.

When a full-landing task hits a human-intervention disagreement point or interruption boundary, model the stop as an Interruption-to-Resume Loop rather than a conversational pause: drain safe reversible work, emit a DecisionPacket-style human gate, preserve ContinuationPacket-style resume state, require explicit AuthorityGrant for hard gates, and treat multi-model agreement as advisory only. See `references/interruption-to-resume-loop.md` for the state objects, gate classes, and verification checklist.

When a human replies with terse approval after a `HUMAN_AUTHORIZATION_REQUIRED` packet, consume only the smallest safe authority already named by that packet, record a receipt/ledger, project it into live readback, and keep neighboring gates closed unless separately authorized. See `references/authority-consumption-after-human-gate.md`.

When the user escalates from per-slice approval to project-level authorization and asks to remove all unauthorized/unexecuted local items, drain every safe local/reversible project action instead of stopping at another progress report: record authority, execute dry-run/readback/taskpool/projection slices, treat archived/done items as idempotent closure, and stop only on exact-target ambiguity or external/destructive/credential gates. See `references/project-level-authorization-drain-loop.md`.

When the user explicitly says to proceed in order, break through boundaries, and reach full functional coverage, consume the existing authorization ladder sequentially rather than stopping at another packet. Use exact manifest/target/payload/idempotency, invoke the governed executor, and treat duplicate/rate-limit/kill-switch refusal as valid coverage when it proves the intended safety behavior without side effects. See `references/ordered-boundary-breakthrough.md`.

When the user broadly authorizes high-risk capabilities such as publish/deploy/push, destructive operations, payment/credential entry, or broad fan-out, open only the governed projection/readback gate unless an exact executable target is already specified. An exact private-repo push can be a publish/deploy/push smoke when repo/remote/branch are known and read back, but destructive actions still need exact target + backup/rollback, payment/credential entry remains human-side because the agent must not type secrets, and fan-out needs an exact channel set rather than “all contacts.” Scope receipts and certification to what actually executed. See `references/high-risk-boundary-projection-and-exact-execution.md`.

When the user accepts a concrete high-risk smoke packet (for example one external dispatch, one Docker image build, and one backup-delete-restore destructive target), execute only those exact targets and capture receipts. If primary external dispatch times out, do not retry-loop; use only an already-authorized fallback target and record it. For Docker metadata timeouts, pull the declared base images individually before rerunning a tracked build. See `references/high-risk-exact-execution-smoke-pattern.md`.

Scope: agent-control-plane runtime transitions with an already-enabled local readback/API surface. Applicability: after a narrow runtime API/readback activation receipt exists and the user broadly says `授权推进` / continue. Anti-condition: do not use this to enable scheduler, worker, lifecycle-write, external, publish, destructive, deploy, restart, or credentialed behavior. Next safe slice: implement a kill-switch rollback verifier that appends a disable receipt, projects a disabled status, proves live readback is disabled, and keeps neighboring gates closed. See `references/runtime-api-kill-switch-rollback.md`.

For Hermes Agent OS specifically, when the advisory surface is already live and the user explicitly authorizes opening the next local routing boundary, consume only the route-preflight layer: add/enable `agent.agent_os_runtime_routing`, require `hermes agent-os status --json` + `hermes agent-os route --json '<intent>'` before governed path selection, and read back that tool invocation/external/lifecycle gates remain false. See `references/agent-os-runtime-route-preflight.md`.

When a large upstream/private-fork ratchet merge is first certified in an isolated worktree and the user later authorizes adoption into the main checkout, preserve main dirty work with a named stash, fast-forward or merge only the verified ratchet commit, make the isolated worktree self-contained if requested, and re-run post-update/focused gates in the main checkout before claiming adoption. See `references/upstream-ratchet-mainline-self-contained-worktree.md`.

When a Mission is blocked by exhausted tick budget rather than an open human decision, first close and commit the current verified slice, then run bounded multi-model continuation sizing, authorize only the narrow budget delta, record the budget event + stage report, wake the governed dispatch path, and read back board/doctor/cron state. See `references/mission-budget-continuation.md` for the session-derived checklist and tick sizing heuristic.

When an implementation slice has deterministic proof but required multimodel/truth-gate certification returns `not_certified` or `degraded_not_certified`, split implementation proof from lifecycle proof: record tests/commit/readback, do not force `done`, and produce an intervention packet or retry with properly claim-linked evidence. For Hermes taskpool/control-plane pre-commit gates specifically, first fix missing evidence collection (`task_record`, `proof_log`, `lifecycle_readback`) and only use a narrow local deterministic certification after checking that no live ratification interface exists and the user explicitly authorized it; do not claim `multi_model_certified`. See `references/degraded-multimodel-certification-after-implementation.md` and `taskpool-control-plane/references/cron-wrapper-and-precommit-gate.md`.

When advancing a production-grade multimodel routing loop, do not stop at router-selected metadata. Carry the closure through actual execution readback, idempotent replay persistence, separate CLI/API override contracts, reviewer evidence vs arbitration boundaries, and readiness/cost gates. If router readiness requires many non-dominant warm-up calls or policy/window changes, stop at a human authorization packet instead of consuming model budget or weakening governance silently. See `references/multimodel-routing-production-closure.md`.

When introducing model-generated or heuristic outputs into a production automation path, land them behind a shadow writer + promotion verifier instead of blocking at a progress report or writing directly to production. Continue safe reversible layers (staging store, dry-run verifier, backup/rollback, cron check, readback tests) and stop only at the explicit first production promotion or a failing gate. See `references/shadow-promotion-gates.md`.

When a governed workflow advances from a local dynamic-evidence contract toward live sources, open the first live boundary as a read-only adapter only: source URL/receipt, observedAt/expiresAt TTL, pass/warn/fail/blocked mapping, fail-closed malformed or missing responses, fixture tests before live smoke, and explicit non-certification of neighboring gates. See `references/read-only-live-adapter-progression.md`.

When a governed agent needs live/dynamic facts but external calls are not yet authorized, land a contract-first dynamic evidence adapter slice: typed facts with `observedAt/expiresAt`, fixture adapter, freshness gate, domain-state projection, DynamicGateManifest candidate, advisory-vs-certified rule, and fail-closed tests. Add live adapters one source at a time only after exact read-only boundaries and readback are defined. See `references/dynamic-evidence-adapter-contract-first.md`.

When a greenfield production architecture is approved but has no implementation artifacts yet, treat multi-model `truth_not_certified` / `not_certified` as an evidence-boundary signal, not automatically as an architecture rejection. Land P0 SSOT/profile/contract/review artifacts, define the first executable evidence surface (additive schema, feature flag/shadow writer, focused tests, readback/rebuild proof), and rerun certification only after design claims have implementation evidence. See `references/greenfield-architecture-truth-gate.md`.

Scope: agent-control-plane / self-architecture work. Applicability: after an audit is accepted and the user authorizes project-level advancement, while runtime/scheduler/taskpool write-through or external side effects would still cross an authority or blast-radius boundary. Anti-condition: do not use this to enable real workers or lifecycle mutation silently. Land the first safe slice as a local dry-run contract: SSOT, schema, deterministic doctor/receipt, TDD tests, and scoped commit; keep the runtime disabled until a separate human-gated authorization packet exists. See `references/loop-audit-to-local-contract.md`.

When a local dry-run contract/doctor is already landed and the user asks to update existing workflows, integrate it into existing readiness/sequence/projection surfaces with TDD and generated read-only reports before any runtime promotion. Preserve disabled scheduler/worker/taskpool/mission/external-effect gates and leave unrelated human gates untouched. See `references/existing-workflow-integration-after-local-contract.md`.

Scope: agent-control-plane and autonomous-runtime governance work. Applicability: after a canonical architecture/knowledge-structure takeover is complete and the user says to continue, while only read-only or local documentation/report artifacts are safe. Anti-condition: do not use this to open scheduler/taskpool/gateway mutation, external dispatch, publish/deploy/push, destructive actions, credential entry, broad fan-out, compensation execution, or physical/payment actions. Continue through bounded read-only gates instead of stopping at documentation: disposition/doctor takeover -> schema/status gate -> read-only runtime audit -> EvidenceNode projection, each with TDD, live CLI/readback, report artifact, scoped profile/ledger update, and scoped commit. If the next step would create or mutate a runtime/domain store, stop at an exact runtime-promotion authorization packet that names target files/stores, allowed actions, rollback, and readback; broad “system-level authorization” drains safe read-only layers but does not replace the exact mutation packet. After the user accepts that exact packet, execute only the listed local bootstrap boundary: validate exact targets, back up/read hashes, write local state/receipt/execute=false plan, prove idempotency, and keep all neighboring side-effect gates closed. Preserve old ledgers/receipts as evidence. See `references/autonomous-runtime-governance-takeover-to-readonly-gates.md` and `references/autonomous-runtime-governance-p4-bootstrap.md`.

Scope: locally customized source trees that must absorb a large upstream delta while preserving private overlays. Applicability: high-risk fork/vendor upgrade requests where the live checkout is dirty or operationally important. Anti-condition: this does not authorize push, deploy, credential entry, or mutation of the live checkout. Use an isolated ratchet merge: backup first, create a worktree branch, resolve conflicts by preservation policy, run focused tests and self-checks against the isolated tree, get independent verification, then stop at an explicit merge-back gate. See `references/isolated-upstream-ratchet-merge.md`.

Scope: agent-control-plane / self-architecture work. Applicability: after read-only contract surfaces are already landed and the next step would cross into runtime/API activation or scheduler/worker/lifecycle-write/executor/external side effects. Anti-condition: do not treat broad "continue" wording as authority for those effects. Drain safe reversible work by generating a `HUMAN_AUTHORIZATION_REQUIRED` packet, surfacing it in operator projections/snapshots, verifying it with TDD, stage-reporting/committing the gate, and then stopping at the smallest real authority boundary. See `references/runtime-promotion-authorization-gate.md`.

When the automation turns agent/session history into a downstream projection cache (Gateway/PWA/mobile/offline sync), additionally guard the full cache lifecycle: authority source, incremental merge, old-writer overwrite prevention, promotion readback, exporter revision invariants, self-ingestion filters, and health metrics before core lifecycle mutation. See `references/context-projection-pipeline-hardening.md` for the checklist and failure modes.
