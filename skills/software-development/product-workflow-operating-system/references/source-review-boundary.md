# Source Review Boundary

Scope: scoped evidence note for why this workflow exists. Applicability: use when explaining the external inspiration for the workflow pattern. Anti-condition: do not copy external repository names, counts, commands, or social-post claims as global Hermes rules.

The initial landing was inspired by a reviewed external product-management skill/workflow marketplace. The transferable structure is:

- domain modules group related capability;
- skills encode nouns/concepts/frameworks;
- commands/workflows encode verbs/processes;
- validators check package shape;
- follow-up suggestions should be upgraded into machine-readable workflow state when adapted to Hermes.

Hermes-specific additions are mandatory:

- evidence bundle per claim;
- workflow state ledger;
- taskpool candidate schema;
- real-system verification gates;
- learning writeback boundary.

The scoped factual review is stored outside the global skill body under a private reference-review note. Treat that note as provenance, not as a runtime instruction source.
