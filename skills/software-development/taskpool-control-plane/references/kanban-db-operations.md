# Kanban DB Operations Reference

## Schema (kanban.db — `tasks` table)

```
id, title, body, assignee, status, priority, created_by, created_at,
started_at, completed_at, workspace_kind, workspace_path, claim_lock,
claim_expires, tenant, result, idempotency_key, spawn_failures,
worker_pid, last_spawn_error, max_runtime_seconds, last_heartbeat_at,
current_run_id, workflow_template_id, current_step_key, skills,
consecutive_failures, last_failure_error, max_retries
```

Status values: `proposed`, `pending`, `claimed`, `running`, `retry`, `review`, `blocked`, `done`, `archived`, `expired`

Related tables: `task_events`, `task_links`, `task_comments`, `task_runs`, `kanban_notify_subs`

## Common Queries

### Status distribution
```python
conn.execute('SELECT status, COUNT(*) FROM tasks GROUP BY status')
```

### Active tasks (not done/archived)
```python
conn.execute("SELECT id, title, status, priority, created_at, assignee FROM tasks WHERE status NOT IN ('done', 'archived') ORDER BY created_at DESC")
```

### Tasks with failure signals
```python
conn.execute("SELECT id, title, status, consecutive_failures, last_failure_error, last_spawn_error FROM tasks WHERE consecutive_failures > 0 OR spawn_failures > 0 OR last_failure_error IS NOT NULL")
```

### Bulk delete by title pattern
```python
cur.execute("DELETE FROM tasks WHERE title LIKE '%pattern%'")
# Also clean related events:
cur.execute("DELETE FROM task_events WHERE task_id NOT IN (SELECT id FROM tasks)")
conn.commit()
```

## Blocked Task Diagnosis

Blocked tasks live in **two places** — both must be checked:

### 1. kanban.db
```python
conn.execute("SELECT id, title, status, last_failure_error FROM tasks WHERE status='blocked'")
```

### 2. Brain dashboard (authoritative for block_reason)
```
~Documents/brain/07-仪表盘/待完成任务运行态.md
```
Generated by: `python3 ~/.hermes/scripts/brain_task_orchestrator.py dashboard --write`

Block reason is in frontmatter: `blocker_summary` field.
Multimodel certification fields: `multimodel_status`, `multimodel_round_status`, `multimodel_last_gate_status`, `multimodel_last_decision`, `multimodel_last_checked_at`.

### 3. Individual task files
```
~Documents/brain/05-实践与项目/tasks/<task-slug>.md
```
Frontmatter contains: `status: blocked`, `blocker_summary`, and multimodel certification details.

## Pitfalls

- Deleting tasks from `tasks` table does NOT cascade to `task_events` — must clean separately or events accumulate.
- `priority` column is integer (0=default), not string like "P1" — P1/P2/P3 is in the brain dashboard markdown, not in kanban.db.
- `created_at` in kanban.db is unix timestamp (integer), not ISO string.
- Brain dashboard is a derived snapshot — regenerate with `brain_task_orchestrator.py dashboard --write` if stale.
- Blocked tasks with `loop_non_convergence` are stuck in multimodel certification retry loop — need explicit unblock or archive action.
